# Research IQ 🔬

Research IQ is an AI-powered research assistant that ingests papers from **arXiv**, indexes them for hybrid search, and lets you ask natural-language questions answered with citations back to the source papers — powered by a local LLM via **Ollama**.

## Features

- **Automated paper ingestion** — fetches papers from the arXiv API for any search query.
- **Hybrid retrieval** — combines **BM25** (keyword search) and **FAISS** (dense vector search) results using Reciprocal Rank Fusion (RRF).
- **Cross-encoder reranking** — reranks fused candidates with a `cross-encoder/ms-marco-MiniLM-L-6-v2` model for higher precision.
- **Query rewriting** — rewrites vague user questions into sharper search queries before retrieval.
- **Local LLM generation** — answers are generated by a local `llama3.2` model through Ollama, with no external API calls.
- **Source-grounded answers** — every answer returns the paper titles and links it was derived from.
- **Lightweight frontend** — a vanilla HTML/CSS/JS chat interface, plus a table view of the indexed papers database.

## Tech Stack

| Layer | Technology |
|---|---|
| Backend API | FastAPI, Uvicorn |
| Paper source | arXiv API (via `httpx` + `feedparser`) |
| Storage | SQLite |
| Keyword search | `rank-bm25` |
| Vector search | `faiss-cpu`, `sentence-transformers` (`all-MiniLM-L6-v2`) |
| Reranking | `sentence-transformers` `CrossEncoder` (`ms-marco-MiniLM-L-6-v2`) |
| Chunking | `langchain-text-splitters` |
| LLM inference | Ollama (`llama3.2`) |
| Frontend | HTML, CSS, JavaScript |

## Prerequisites

- Python 3.10+
- [Ollama](https://ollama.com/) installed and running locally, with the `llama3.2` model pulled:
  ```bash
  ollama pull llama3.2
  ```

## Setup & Installation

1. **Clone the repository**
   ```bash
   git clone <your-repo-url>
   cd res-rag
   ```

2. **Create a virtual environment and install dependencies**
   ```bash
   cd backend
   python -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   pip install -r requirement.txt
   ```

3. **Start Ollama** (in a separate terminal)
   ```bash
   ollama serve
   ```

4. **Run the backend API**
   ```bash
   uvicorn main:app --reload --port 8000
   ```
   On first run, `data/` is created automatically and indexes are built if papers already exist in the database.

5. **Open the frontend**
   Open `frontend/index.html` directly in your browser (it talks to `http://127.0.0.1:8000` by default).

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Health check |
| `POST` | `/ingest?query=...&total=...&batch_size=...` | Fetch papers from arXiv and rebuild indexes |
| `GET` | `/papers` | List all ingested papers |
| `GET` | `/ask?question=...` | Ask a question and get an answer with sources |

### Example: Ingest papers
```bash
curl -X POST "http://127.0.0.1:8000/ingest?query=biophysics&total=50&batch_size=20"
```

### Example: Ask a question
```bash
curl "http://127.0.0.1:8000/ask?question=What%20is%20protein%20folding?"
```

## How It Works

1. **Ingestion** — Papers are fetched from arXiv in batches and stored in SQLite.
2. **Chunking** — Title + abstract text is split into overlapping chunks (`chunk_size=1000`, `overlap=150`).
3. **Indexing** — Chunks are indexed with BM25 (keyword) and embedded + stored in a FAISS index (dense vectors).
4. **Query time** — The user's question is rewritten by the LLM, searched via BM25 and FAISS in parallel, fused with RRF, reranked with a cross-encoder, and the top chunks are passed as context to `llama3.2` to generate the final answer with cited sources.

## Notes

- Generated index files (`*.pkl`, `*.index`) and the SQLite database in `backend/data/` are excluded from version control — they're rebuilt automatically from `/ingest`.
- CORS is currently open (`allow_origins=["*"]`) for local development; restrict this before deploying publicly.
